# Firestore Schema Design

This document describes the data model for the Department Inventory & Equipment
Management System. It is the source of truth that the TypeScript types in
`src/lib/types.ts` mirror.

## Design principles

- **Single flat collection.** All assets — lab equipment, chemicals, IT gear,
  office supplies — live in one `items` collection. A `category` field
  discriminates them. This keeps real-time queries and dashboard aggregation
  simple (one listener), while category-specific fields (e.g. `expiryDate`)
  are optional on the shared shape.
- **Real-time first.** The dashboard attaches a single `onSnapshot` listener to
  `items`, so any create/update/delete on any client propagates instantly with
  no page refresh. Aggregates (totals, low-stock, status distribution) are
  computed client-side from that live list — no fan-out writes or counters to
  keep in sync.
- **Server timestamps.** `createdAt` / `updatedAt` are written with
  `serverTimestamp()` so ordering is consistent across clients and clocks.

## Collection: `items`

Document id: auto-generated by Firestore. The id is exposed on the client as
`InventoryItem.id` but is **not** stored inside the document body.

| Field          | Type                    | Required | Notes                                                                 |
| -------------- | ----------------------- | -------- | --------------------------------------------------------------------- |
| `name`         | `string`                | ✅       | Human-readable item name.                                             |
| `assetCode`    | `string`                | ➖       | Department asset code / รหัสครุภัณฑ์ (e.g. `SCI-CHEM-001`).            |
| `category`     | `string` (enum)         | ✅       | One of the category keys below.                                       |
| `description`  | `string`                | ➖       | Free text.                                                            |
| `quantity`     | `number`                | ✅       | On-hand count. Durable goods are usually `1`.                         |
| `unit`         | `string`                | ✅       | e.g. `unit`, `box`, `bottle`, `ml`.                                   |
| `minQuantity`  | `number`                | ✅       | Low-stock threshold; `quantity <= minQuantity` ⇒ low-stock alert.     |
| `status`       | `string` (enum)         | ✅       | Real-time status of the asset (below).                               |
| `location`     | `string`                | ➖       | Room / cabinet / shelf.                                               |
| `custodian`    | `string`                | ➖       | Person responsible / ผู้ดูแล.                                          |
| `expiryDate`   | `Timestamp \| null`     | ➖       | Meaningful for `reagents_chemicals`.                                  |
| `acquiredDate` | `Timestamp \| null`     | ➖       | Purchase / acquisition date.                                          |
| `unitPrice`    | `number`                | ➖       | Purchase cost in THB (faculty asset reporting).                       |
| `notes`        | `string`                | ➖       | Free text.                                                            |
| `createdAt`    | `Timestamp`             | ✅       | Set via `serverTimestamp()` on create.                               |
| `updatedAt`    | `Timestamp`             | ✅       | Set via `serverTimestamp()` on every write.                          |

### `category` enum

| Key                  | English                 | Thai                 | Tracks expiry |
| -------------------- | ----------------------- | -------------------- | ------------- |
| `lab_equipment`      | Lab Equipment           | ครุภัณฑ์วิทยาศาสตร์  | no            |
| `reagents_chemicals` | Reagents / Chemicals    | สารเคมี / รีเอเจนต์  | **yes**       |
| `it_computing`       | IT / Computing Devices  | อุปกรณ์คอมพิวเตอร์   | no            |
| `office_supplies`    | General Office Supplies | วัสดุสำนักงาน        | no            |

### `status` enum

| Key           | Meaning                          | Thai                |
| ------------- | -------------------------------- | ------------------- |
| `available`   | Ready to use                     | พร้อมใช้งาน         |
| `borrowed`    | In-use / borrowed out            | ถูกยืม / ใช้งาน     |
| `maintenance` | Under maintenance / broken       | ซ่อมบำรุง / ชำรุด   |
| `retired`     | Decommissioned / disposed        | ปลดระวาง            |

## Derived / computed values (client-side)

These are **not stored**; they are computed from the live snapshot in
`src/lib/items.ts`:

- **Low stock**: `quantity <= minQuantity`.
- **Expiring soon**: `expiryDate` within `EXPIRING_SOON_DAYS` (default 30).
- **Dashboard aggregates**: `computeStats()` produces totals plus `byStatus`
  and `byCategory` maps in a single pass.

## Indexes

The default single-field indexes cover the current queries
(`orderBy("name")`). When we later add filtered + sorted queries (e.g. filter
by `category` and order by `expiryDate`), add matching composite indexes to
`firestore.indexes.json`; the Firebase console will also emit the exact index
link on first run.

## Security rules

`firestore.rules` restricts all access to authenticated staff whose Google
account is on the department's Workspace domain (`@g.swu.ac.th`), and
shape-validates writes (required fields, valid `category`/`status`, non-negative
quantities). The web app mirrors the same domain check in `src/lib/auth.ts` for
UX, but the rules are the real enforcement boundary. Deploy with
`firebase deploy --only firestore:rules`.

## Future collections (not yet implemented)

- `loans` — borrow/return history per item (who, when, due date) to power an
  audit trail beyond the current status flag.
- `users` — staff directory + roles once Firebase Auth is added.
